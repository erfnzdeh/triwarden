# Standalone SSH approval

Apply the user's requested Secrets approval approach to SSH signatures: a small standalone, resizable panel using the app's form cards, background, capsule actions and live countdown. It must appear without opening the vault or menu-bar window and without activating every Triwarden window. Use the app's existing nonactivating-panel pattern, keep it visible while another app has focus, and allow keyboard interaction without becoming a main window.

Keep requester, tool, key and full paths readable. Preserve the four existing grant durations, repeat-request emphasis and normal macOS device-owner authentication. Closing or Escape denies the displayed request. Notification/menu-bar reveal opens only this panel. Existing manually opened inline approval entry points remain available.

The queue supplies the monotonic deadline used by the countdown and timeout checks. Bind panel actions to the displayed prompt ID so stale actions cannot answer the next queued request. Hide the decision panel during device authentication, then reveal the next pending request. Lock/reset/agent stop dismiss the panel and cancel outstanding authorization.

Implementation: expose the queue deadline and test timeout promotion/stale actions; add a pure SSH form and independent panel owner; route SSHAgentService presentation/reveal through that owner; add isolated synthetic preview/presentation diagnostics; run package regressions, a signed build and visual checks. Presentation diagnostics must use no real keys, vault or authentication, and verify that an inactive-app panel stays visible while an ordinary witness window stays hidden.

Validation on 2026-10-21: 155 package tests pass (80 API, 28 crypto, 25 Secrets, 22 SSH). Queue regressions cover the exact deadline, next-request promotion, stale decisions, joined requests retaining their deadline, and expired Allow before the periodic watcher runs. The signed Debug app builds. The native `--selftest-ssh-presentation` diagnostic passes eight checks: Finder remains the foreground app, Dock policy stays accessory, a hidden ordinary witness window stays hidden, the actual production approval panel is unoccluded on the active Space, revealing it still leaves the witness hidden, and close/dismissal produce only the intended denial.

The diagnostic runs a real AppKit event loop and yields during waits before any AppModel is created. Nested RunLoop waiting inside the synchronous probe did not dispatch the window events needed to update occlusion state. AppKit can report `isActive=true` for the key-taking panel while `NSWorkspace.frontmostApplication` remains Finder; the probe verifies the actual foreground process rather than treating that internal flag as proof that all app windows were activated. All six light/dark/compact/repeat/long/urgent previews were exported and visually inspected, and the final app/nested signature verification passed. This covers the current desktop, not every fullscreen/Spaces configuration. Device-owner authentication uses the existing production path; no new user-assisted SSH signing test was performed for this presentation change. Independent review was unavailable due the review agent's service usage limit; the diff was reviewed locally.

Run `make selftest-ssh-presentation` on an unlocked GUI desktop. `--selftest-ssh-preview` renders six reference-only light/dark/compact/repeat/long/urgent forms and supports the existing `TRIWARDEN_SNAPSHOT_STDOUT=1` export. Both diagnostics are Debug-only and use no vault, real private key, signing payload, live agent socket or authentication bypass.
